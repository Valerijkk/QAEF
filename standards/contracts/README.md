# Машиночитаемые контракты

Этот каталог задаёт строгие переносимые записи для задачи, контекста, оценки, проверки и передачи результата. Контракт описывает данные, но не выдаёт полномочий и не заменяет наблюдаемое evidence.

## Общие правила

- Все пять схем используют JSON Schema и запрещают неописанные свойства в корневом объекте и во всех вложенных объектах.
- `mode` всегда означает ровно один выбранный режим: `existing` или `greenfield`.
- `status` всегда один из `PASS`, `FAIL`, `UNKNOWN`, `NOT_RUN`, `BLOCKED`.
- `PASS` допустим только там, где схема требует непустое evidence: наблюдения для оценки, evidence и успешные проверки для отчёта, evidence для передачи.
- Идентификаторы и пути задаёт пользователь или целевой проект. Контракты не навязывают префиксы, структуру каталогов или среду исполнения.
- В `UNKNOWN`, `NOT_RUN` и `BLOCKED` пустое evidence не заменяется уверенной формулировкой; ограничение или неизвестное фиксируется явно.

## `task-contract.schema.json`

| Свойство | Значение |
|---|---|
| `$schema` | Технический идентификатор диалекта JSON Schema. |
| `$id` | Относительный идентификатор этой схемы. |
| `objective` | Наблюдаемый результат задачи. |
| `mode` | Выбранный режим `existing` или `greenfield`. |
| `scope` | Граница разрешённой и исключённой области. |
| `scope.allowed_paths` | Пути, с которыми разрешена работа. |
| `scope.excluded_paths` | Пути, которые исключены из работы. |
| `authority` | Фактически выданные права на действия. |
| `authority.read` | Разрешено ли чтение. |
| `authority.write` | Разрешена ли запись. |
| `authority.execute` | Разрешено ли выполнение. |
| `authority.egress` | Разрешена ли внешняя передача. |
| `inputs` | Использованные входы задачи. |
| `inputs[].kind` | Вид входа. |
| `inputs[].path` | Ссылка или путь к входу в пределах задачи. |
| `inputs[].provenance` | Происхождение входа. |
| `constraints` | Обязательные ограничения работы. |
| `acceptance` | Условия приёмки. |
| `unknowns` | Неизвестные или неразрешённые вопросы. |

Минимальный допустимый пример:

```json
{
  "objective": "Добавить один тест",
  "mode": "greenfield",
  "scope": {"allowed_paths": ["tests/example"], "excluded_paths": []},
  "authority": {"read": true, "write": false, "execute": false, "egress": false},
  "inputs": [],
  "constraints": ["Не выходить за границы задачи"],
  "acceptance": ["Результат сохранён"],
  "unknowns": []
}
```

## `context-packet.schema.json`

| Свойство | Значение |
|---|---|
| `$schema` | Технический идентификатор диалекта JSON Schema. |
| `$id` | Относительный идентификатор этой схемы. |
| `task` | Краткое описание задачи, для которой собран контекст. |
| `task.objective` | Наблюдаемый результат этой задачи. |
| `task.mode` | Выбранный режим `existing` или `greenfield`. |
| `sources` | Источники, способные повлиять на решение. |
| `sources[].path` | Ссылка или путь к источнику. |
| `sources[].kind` | Вид источника. |
| `sources[].freshness` | Дата, ревизия либо `UNKNOWN` для свежести источника. |
| `sources[].provenance` | Происхождение источника. |
| `facts` | Наблюдаемые факты с опорой на источники. |
| `inferences` | Выводы, отделённые от фактов. |
| `unknowns` | Недостающая, противоречивая или непроверенная информация. |
| `redactions` | Что было исключено из контекста и по какой причине. |

Минимальный допустимый пример:

```json
{
  "task": {"objective": "Понять границу", "mode": "existing"},
  "sources": [],
  "facts": [],
  "inferences": [],
  "unknowns": ["Контекст ещё не собран"],
  "redactions": []
}
```

## `evaluation-record.schema.json`

| Свойство | Значение |
|---|---|
| `$schema` | Технический идентификатор диалекта JSON Schema. |
| `$id` | Относительный идентификатор этой схемы. |
| `$schema` в экземпляре | Необязательная относительная ссылка на контракт; допустимо ровно `../standards/contracts/evaluation-record.schema.json`. |
| `subject` | Предмет оценки. |
| `rubric` | Критерии и ожидаемое наблюдаемое состояние. |
| `rubric[].criterion` | Название критерия. |
| `rubric[].expected` | Ожидаемое состояние по критерию. |
| `observations` | Зафиксированные наблюдения. |
| `observations[].statement` | Формулировка наблюдения. |
| `observations[].evidence` | Ссылка на evidence наблюдения. |
| `negative_cases` | Контрпримеры или негативные сценарии. |
| `negative_cases[].case` | Описанный негативный сценарий. |
| `negative_cases[].result` | Наблюдаемый результат сценария. |
| `status` | Итог: `PASS`, `FAIL`, `UNKNOWN`, `NOT_RUN` или `BLOCKED`. Для `PASS` требуется хотя бы одно наблюдение с evidence. |

Минимальный допустимый пример:

```json
{
  "$schema": "../standards/contracts/evaluation-record.schema.json",
  "subject": "Новая проверка",
  "rubric": [],
  "observations": [],
  "negative_cases": [],
  "status": "NOT_RUN"
}
```

## `verification-report.schema.json`

| Свойство | Значение |
|---|---|
| `$schema` | Технический идентификатор диалекта JSON Schema. |
| `$id` | Относительный идентификатор этой схемы. |
| `claim` | Проверяемое утверждение. |
| `evidence` | Наблюдаемые материалы проверки. |
| `evidence[].kind` | Вид evidence. |
| `evidence[].locator` | Ссылка или указатель на evidence. |
| `evidence[].result` | Зафиксированный результат evidence. |
| `checks` | Отдельные проверки утверждения. |
| `checks[].name` | Название проверки. |
| `checks[].status` | Статус отдельной проверки из общего набора статусов. |
| `checks[].evidence_refs` | Ссылки на evidence этой проверки; для `PASS` они обязательны. |
| `status` | Итог отчёта. Для `PASS` требуются evidence и хотя бы одна успешная проверка. |
| `limitations` | Границы применимости и непроверенные части. |

Минимальный допустимый пример:

```json
{
  "claim": "Проверка ещё не запускалась",
  "evidence": [],
  "checks": [],
  "status": "NOT_RUN",
  "limitations": ["Наблюдаемого evidence пока нет"]
}
```

## `handoff.schema.json`

| Свойство | Значение |
|---|---|
| `$schema` | Технический идентификатор диалекта JSON Schema. |
| `$id` | Относительный идентификатор этой схемы. |
| `result` | Состояние передаваемого результата. |
| `changed_paths` | Список изменённых путей. |
| `evidence` | Наблюдаемые материалы, подтверждающие результат. |
| `evidence[].kind` | Вид evidence. |
| `evidence[].locator` | Ссылка или указатель на evidence. |
| `evidence[].result` | Зафиксированный результат evidence. |
| `status` | Итог передачи. Для `PASS` требуется хотя бы одно evidence. |
| `risks` | Открытые риски, допущения или остаточные проблемы. |
| `next_action` | Одно следующее действие владельца передачи. |

Минимальный допустимый пример:

```json
{
  "result": "Работа ожидает проверки",
  "changed_paths": [],
  "evidence": [],
  "status": "NOT_RUN",
  "risks": ["Проверка не проводилась"],
  "next_action": "Провести проверку"
}
```
