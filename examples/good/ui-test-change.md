# Принятый пример: изменение UI-теста

## Запрос

> Режим `existing`. Проверить, что при вводе купона с истёкшим сроком пользователь видит сообщение об отказе, а итоговая сумма не меняется. Разрешено изменить только существующий UI-файл компонента корзины.

## Выбранный контекст

| Источник | Наблюдаемый факт | Решение, которое он поддерживает |
|---|---|---|
| `specs/checkout.md` | Просроченный купон отклоняется; итог остаётся прежним. | Oracle и user-visible результат. |
| `src/checkout/CartSummary.tsx` | Ошибка выводится в элементе с `role="alert"`; итог помечен `data-testid="cart-total"`. | Наблюдаемая семантика вместо селекторов по классам. |
| `tests/ui/checkout/CartSummary.test.tsx` | Файл использует `@testing-library/react`, запросы по роли и тексту. | Существующий стиль и сохраняемый путь. |

**Факты:** сообщение об ошибке уже доступно через accessibility-роль; итог имеет стабильный тестовый идентификатор.

**Вывод:** сценарий выражается через то, что видит пользователь, поэтому проверка не привязывается к структуре разметки и не ломается при рефакторинге вёрстки.

**Неизвестное:** подтверждённая команда запуска UI-слоя не предоставлена.

## Сохранённый путь

- `tests/ui/checkout/CartSummary.test.tsx`

Сохранённое изменение:

```tsx
it("rejects an expired coupon and keeps the total unchanged", async () => {
  const user = userEvent.setup();
  render(<CartSummary items={twoItems} total={2400} />);

  await user.type(screen.getByLabelText("Промокод"), "EXPIRED2024");
  await user.click(screen.getByRole("button", { name: "Применить" }));

  expect(await screen.findByRole("alert")).toHaveTextContent("Срок действия купона истёк");
  expect(screen.getByTestId("cart-total")).toHaveTextContent("2400");
});
```

## Evidence

- Статическое evidence: код сохранён в существующем UI-файле; новый helper не извлекался.
- Traceability: `specs/checkout.md` → правило отклонения просроченного купона → один сценарий с двумя наблюдениями.
- Assertions наблюдают user-visible результат: текст сообщения и неизменившийся итог. Факт рендера без поведения не проверяется.
- Запросы идут по роли и подписи, а не по классам вёрстки: сценарий переживает рефакторинг разметки.
- Второе наблюдение — итог `2400` — защищает от ложного успеха, при котором ошибка показана, но сумма всё равно пересчитана.
- Чувствительность assertion не наблюдалась: controlled mutation не запускалась.
