# Принятый пример: профиль нагрузки

## Запрос

> Режим `existing`. Зафиксировать профиль нагрузки для чтения каталога: подтверждённый дневной пик — `120` запросов в секунду в течение `10` минут. Разрешено изменить только существующий каталог нагрузочных сценариев.

## Выбранный контекст

| Источник | Наблюдаемый факт | Решение, которое он поддерживает |
|---|---|---|
| `docs/capacity.md` | Наблюдённый дневной пик `GET /catalog` — `120` rps, длительность плато `10` минут. | Модель трафика с provenance, а не выдуманное число. |
| `specs/catalog.md` | Целевой отклик `p95 < 400 мс` при пиковой нагрузке. | Порог, по которому профиль имеет смысл. |
| `perf/scenarios/search.js` | Проектный инструмент — k6; сценарии экспортируют `options` и default-функцию. | Подтверждённый нативный стек и стиль. |
| `perf/README.md` | Запуск выполняется командой проекта из CI; окружение готовит платформенная команда. | Владелец исполнения — не QAEF. |

**Факты:** и профиль трафика, и порог отклика взяты из проектных документов.

**Вывод:** профиль воспроизводит наблюдённый пик, а не произвольную «стресс-нагрузку»; порог задан как порог сценария, чтобы прогон имел наблюдаемый исход.

**Неизвестное:** фактическая мощность тестового стенда и его сопоставимость с production — `UNKNOWN`.

## Сохранённый путь

- `perf/scenarios/catalog-read.js`

Сохранённое изменение:

```js
import http from "k6/http";
import { check } from "k6";

export const options = {
  scenarios: {
    catalog_daily_peak: {
      executor: "constant-arrival-rate",
      rate: 120,
      timeUnit: "1s",
      duration: "10m",
      preAllocatedVUs: 200,
    },
  },
  thresholds: {
    "http_req_duration{scenario:catalog_daily_peak}": ["p(95)<400"],
  },
};

export default function () {
  const res = http.get(`${__ENV.CATALOG_BASE_URL}/catalog?page=1`);
  check(res, { "catalog page returns 200": (r) => r.status === 200 });
}
```

## Evidence

- Статическое evidence: сценарий сохранён в существующем проектном каталоге `perf/scenarios/` в нативном для проекта инструменте.
- Traceability: `docs/capacity.md` → пик `120` rps на `10` минут → параметры `rate` и `duration`; `specs/catalog.md` → `p95 < 400 мс` → threshold сценария.
- Базовый адрес читается из переменной окружения: адреса и учётные данные в файл не записаны.
- Порог задан как threshold, поэтому у прогона есть наблюдаемый исход, а не только графики.
- QAEF не поставляет раннер, установщик и окружение: k6, стенд и команда запуска принадлежат целевому проекту.

## Честный статус

- Артефакт подготовлен: да; показаны сохраняемый путь и содержимое.
- Статус выполнения: `NOT_RUN` — нагрузочный прогон не запускался.
- Поведение целевой системы под нагрузкой: `UNKNOWN`.
- Остаточный риск: сопоставимость стенда с production не подтверждена, поэтому результат будущего прогона нельзя переносить на production без отдельного evidence.
