# Принятый пример: изменение unit-теста

## Запрос

> Режим `existing`. Добавить unit-проверки границы начисления штрафа: в срок штраф равен нулю, первый день просрочки стоит `50`. Разрешено изменить только существующий unit-файл.

## Выбранный контекст

| Источник | Наблюдаемый факт | Решение, которое он поддерживает |
|---|---|---|
| `specs/loans.md` | При `daysLate = 0` штраф равен `0`; с первого дня начисляется `50` за день. | Существенный oracle и boundary. |
| `src/billing/late-fee.ts` | Экспортируется функция `calculateLateFee(daysLate)`. | Unit-граница. |
| `tests/unit/billing/late-fee.test.ts` | Файл импортирует `describe`, `expect`, `it` из `vitest` и `calculateLateFee` из `../../../src/billing/late-fee`; сценарии именуются по поведению. | Подтверждённые imports, существующий стиль и сохраняемый путь. |

**Факты:** два ожидаемых значения заданы спецификацией; стиль теста и unit-слой уже существуют.

**Вывод:** два небольших сценария в существующем файле выражают переход через границу без нового helper.

**Неизвестное:** подтверждённый способ исполнения не указан.

## Сохранённый путь

- `tests/unit/billing/late-fee.test.ts`

Сохранённое изменение:

```ts
import { describe, expect, it } from "vitest";

import { calculateLateFee } from "../../../src/billing/late-fee";

describe("calculateLateFee", () => {
  it("returns zero when the item is returned on the due date", () => {
    expect(calculateLateFee(0)).toBe(0);
  });

  it("charges the first overdue day", () => {
    expect(calculateLateFee(1)).toBe(50);
  });
});
```

## Evidence

- Статическое evidence: код сохранён в существующем unit-файле.
- Traceability: `specs/loans.md` → boundary между `0` и `1` → два именованных сценария.
- Assertions различают два существенных исхода; проверка только факта вызова не используется.
- Чувствительность к изменению ожидаемого значения не наблюдалась.

## Честный статус

- Артефакт подготовлен: да; показаны сохраняемый путь и содержимое.
- Статус выполнения: `NOT_RUN`.
- Поведение целевой системы: `UNKNOWN` до наблюдаемой проверки.
- Остаточный риск: возможное расхождение фактического импорта или реализации со спецификацией не проверено.
