# Отклонённый пример: молчаливая параллельная архитектура

## Задача на реализацию

> Режим `existing`. Добавить API-тест чтения профиля в подтверждённый проектный test-layout.

Подтверждённый контекст указывает `tests/api/`, fixture `api_client` и существующий файл `tests/api/test_profile.py`.

## Отклонённый артефакт

Вместо изменения существующего файла автор создал:

```text
automation/http_client.py
automation/specs/profile_spec.py
automation/config.py
```

Фрагмент отклонённого теста:

```python
from automation.http_client import UniversalClient


def profile_is_readable() -> None:
    response = UniversalClient().get("/profile")
    assert response.status_code == 200
```

## Нарушенный стандарт

- `standards/test-architecture.md`, раздел `existing`: новый тест и support обязаны оставаться внутри доказанной архитектуры.
- `standards/context-quality.md`: подтверждённые соглашения нельзя заменять выводом автора, выданным за факт.

## Почему артефакт отклонён

Новый корень, новый клиент и новая конфигурация не требуются задачей и не имеют доказанного потребителя. Они дублируют уже подтверждённые ответственности, скрывают проектный способ подготовки запроса и расширяют scope без решения пользователя.

## Исправленная форма

Из контекста подтверждены только существующий корень, fixture `api_client` и будущий test-файл. Endpoint, способ идентификации и oracle не предоставлены, поэтому correction сохраняет архитектурную границу и останавливается до кода.

```text
Разрешённый будущий путь: tests/api/test_profile.py
Изменённые пути: отсутствуют
Новый общий клиент или новый test-root: не создаётся
Артефакт подготовлен: нет
Статус задачи: BLOCKED
Статус выполнения: NOT_RUN
Поведение целевой системы: UNKNOWN
```

Для продолжения нужны источники с provenance:

- контракт операции чтения профиля: method, endpoint и наблюдаемый исход;
- подтверждённый проектный способ идентификации, если он нужен сценарию;
- существующий пример вызова `api_client` и чтения ответа.

После получения этих фактов тест сохраняется только в `tests/api/test_profile.py` и использует доказанный `api_client`; новая параллельная архитектура не создаётся.
