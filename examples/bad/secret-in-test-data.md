# Отклонённый пример: реальный секрет в тестовых данных

## Задача на реализацию

> Режим `existing`. Добавить integration-тест выгрузки отчёта в объектное хранилище. Разрешено изменить `tests/integration/test_report_upload.py` и фикстуры в `tests/integration/conftest.py`.

## Отклонённый артефакт

```python
S3_ENDPOINT = "https://storage.internal.acme-corp.example/prod-reports"
S3_ACCESS_KEY = "<реальный ключ, скопированный из .env продовой среды>"
S3_SECRET_KEY = "<реальный секрет, скопированный из .env продовой среды>"
TEST_USER_EMAIL = "<личная почта сотрудника из выгрузки>"
```

Изменённые пути: `tests/integration/test_report_upload.py`, `tests/integration/conftest.py`.

Здесь значения приведены как описание отклонённого содержимого. Сами секреты в этот пример не переносятся — их копирование было бы тем же нарушением.

## Нарушенный стандарт

- `docs/SECURITY-MODEL.md`, раздел «Границы данных и действий»: не включайте в prompt, context, тестовые данные, отчёты или handoff секреты, токены, ключи, персональные данные и лишние журналы.
- `docs/SECURITY-MODEL.md`, там же: для теста используйте минимальные синтетические или явно разрешённые данные; при невозможности безопасной подстановки остановитесь.
- `docs/CONTEXT-ENGINEERING.md`, раздел «Минимизация и сжатие»: приватная топология и полные выгрузки в контекст не включаются.
- `standards/data-handling.md`: классификация и redaction обязательны до сохранения артефакта.

## Почему артефакт отклонён

Нарушены сразу три границы. Первая: рабочий ключ доступа попал в файл, который уйдёт в историю системы контроля версий — удаление в следующем коммите его оттуда не убирает. Вторая: тест направлен на продовый endpoint, то есть негативный сценарий может изменить или удалить реальные отчёты. Третья: личная почта сотрудника — персональные данные, которых в тестовых данных быть не должно.

Ни одно из трёх нарушений не исправляется «аккуратностью при запуске»: артефакт небезопасен уже в сохранённом виде.

## Исправленная форма

Из задачи подтверждены режим, разрешённые пути и намерение проверить выгрузку. Не подтверждены: изолированный endpoint, способ выдачи учётных данных в тестовой среде и владелец очистки. Безопасная correction останавливается до записи.

```text
Разрешённый будущий путь: tests/integration/test_report_upload.py
Изменённые пути: отсутствуют
Артефакт подготовлен: нет
Статус задачи: BLOCKED
Статус выполнения: NOT_RUN
Поведение целевой системы: UNKNOWN
Ограничение: изолированная граница и безопасный источник учётных данных не подтверждены
```

Для продолжения нужны источники с provenance:

- адрес изолированного тестового хранилища, отдельного от production;
- принятый в проекте способ получения учётных данных в тестах — переменная окружения, секрет CI или локальная фикстура — без записи значения в файл;
- владелец подготовки и очистки тестового bucket;
- разрешение на egress к внешнему адресу, если оно требуется.

После их получения в тесте сохраняются только имена переменных и синтетические данные:

```text
endpoint: читается из переменной окружения тестовой среды
учётные данные: не сохраняются в файле ни в каком виде
пользователь: синтетический адрес вида user+report@example.test
цель: изолированный bucket, очищаемый назначенным владельцем
```

Если безопасную подстановку обеспечить нельзя, правильный результат — `BLOCKED`, а не тест с реальным секретом.
