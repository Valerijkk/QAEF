# Отклонённый пример: придуманная команда и ложный статус

## Задача на реализацию

> Режим `existing`. Добавить unit-тест: имя длиной `51` символ отклоняется при максимуме `50`. Разрешено изменить только `tests/unit/test_name_limit.py` и передать честное evidence.

## Отклонённый артефакт

```text
Изменённый путь: tests/unit/test_name_limit.py
Команда: <значение не найдено в источниках и подставлено автором>
Наблюдаемый вывод: <отсутствует>
Статус автора: PASS
```

Здесь `PASS` является частью отклонённой цитаты, а не verdict этого примера.

## Нарушенный стандарт

- `standards/evidence-policy.md`: незапущенная проверка не может быть описана как выполненная, а утверждение не должно быть сильнее evidence.
- `standards/context-quality.md`: отсутствующее проектное сведение должно остаться `UNKNOWN`, а не заполняться догадкой.
- `standards/contracts/verification-report.schema.json`: успешная проверка требует непустых ссылок на evidence.

## Почему артефакт отклонён

Строка команды не имеет provenance, наблюдение отсутствует, а успешный статус невозможно воспроизвести. Даже наличие test-файла подтверждает только статический артефакт, но не его исполнение и не корректность поведения.

## Исправленная форма

```text
Разрешённый будущий путь: tests/unit/test_name_limit.py
Изменённые пути: отсутствуют
Артефакт подготовлен: нет
Статус задачи: BLOCKED
Подтверждённая команда: UNKNOWN
Статус выполнения: NOT_RUN
Поведение целевой системы: UNKNOWN
Ограничение: production interface и наблюдаемое evidence исполнения отсутствуют
```

Из задачи известны boundary `50/51`, режим и путь, но не известны фактический import, сигнатура и принятый стиль теста. Следующий владелец запрашивает production source и существующий unit-пример с provenance. Только после этого сохраняется тест; затем отдельно требуется подтверждённый проектный способ проверки. До получения evidence успешный статус не заявляется.
