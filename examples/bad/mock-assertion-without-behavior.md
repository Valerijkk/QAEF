# Отклонённый пример: assertion на вызов mock вместо поведения

## Задача на реализацию

> Режим `existing`. Добавить unit-тест: при отмене брони клиенту начисляется возврат `70%` от суммы. Разрешено изменить только `tests/unit/booking/test_refund.py`.

## Отклонённый артефакт

```python
from unittest.mock import Mock

from src.booking.refund import process_cancellation


def test_refund_is_issued() -> None:
    gateway = Mock()
    process_cancellation(booking_id=17, gateway=gateway)
    assert gateway.refund.called
```

Изменённый путь: `tests/unit/booking/test_refund.py`.

## Нарушенный стандарт

- `docs/TEST-AUTOMATION.md`, раздел «Качество теста»: assertion проверяет существенный результат, а не только отсутствие ошибки, вызов мока или факт рендера без поведения.
- `docs/EVALUATION.md`, раздел «Негативные sentinels»: тест существует, но не несёт значимого наблюдения о нужной границе.
- `standards/evidence-policy.md`: проверка assertion отделяет чувствительность к управляемому входу от доказательства правильности всей системы.

## Почему артефакт отклонён

Тест наблюдает, что метод был вызван, но не наблюдает **что** было вызвано. Он останется зелёным, если возврат посчитан как `100%`, как `0%` или как отрицательная сумма — то есть при любой ошибке ровно в том правиле, ради которого он написан.

Контрольная проверка чувствительности: если в `process_cancellation` заменить коэффициент `0.7` на `0.3`, тест продолжит проходить. Assertion не связан с oracle задачи.

## Исправленная форма

Из задачи подтверждены только режим, write-scope и правило `70%`. Фактическая сигнатура `process_cancellation`, способ передачи суммы и тип возврата не предоставлены, поэтому correction не придумывает интерфейс.

```text
Разрешённый будущий путь: tests/unit/booking/test_refund.py
Изменённые пути: отсутствуют
Артефакт подготовлен: нет
Статус задачи: BLOCKED
Статус выполнения: NOT_RUN
Поведение целевой системы: UNKNOWN
Ограничение: сигнатура и единица суммы возврата не подтверждены источником
```

Для продолжения нужны источники с provenance:

- сумма исходной брони и ожидаемое значение возврата на конкретном примере;
- production source с фактической сигнатурой и типом возвращаемого значения;
- принятый в проекте способ подмены платёжного шлюза в unit-слое.

После их получения assertion должен наблюдать **сумму** возврата, а не факт вызова:

```text
ожидаемое наблюдение: возврат для брони на 200 равен 140
проверка чувствительности: при коэффициенте 0.3 тест обязан упасть
```

Если проектный стиль допускает проверку аргументов вызова, наблюдать нужно переданное значение суммы, а не булев признак `called`.
