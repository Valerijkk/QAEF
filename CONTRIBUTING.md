# Участие в QAEF

QAEF распространяется на условиях [LICENSE](LICENSE): все права принадлежат
TouchStone Studio, а изменение и создание производных произведений допускается
только по предварительному письменному разрешению владельца.

Поэтому порядок здесь обратный привычному: **сначала согласование, потом код.**
Pull request без предварительно согласованного issue не принимается, даже если
изменение верное по существу.

## Порядок

1. Откройте issue и опишите наблюдаемую проблему или предложение.
2. Дождитесь решения владельца о том, принимается ли направление и в каком объёме.
3. Только после явного разрешения готовьте изменение в согласованных границах.

## Требования к изменению

Изменение принимается, если оно удовлетворяет тем же правилам, которые QAEF
предъявляет к работе агентов.

| Требование | Что это значит |
|---|---|
| Один результат | Один PR решает одну задачу и имеет одного владельца |
| Границы | Изменяются только файлы, согласованные в issue |
| Evidence | Каждое существенное утверждение связано с файлом, наблюдением или явным ограничением |
| Разделение | Факт, вывод и `UNKNOWN` не смешиваются |
| Честный статус | Непроверенное — `UNKNOWN`, незапущенное — `NOT_RUN`, требующее решения — `BLOCKED` |
| Согласованность | `MANIFEST.md` обновлён, если состав поставки изменился |

## Что отклоняется без обсуждения

- Утверждение о готовности, отсутствии дефектов, ROI, производительности или
  превосходстве над другим подходом без соразмерного evidence.
- Заявленный `PASS` без наблюдения, которое можно повторить.
- Секреты, токены, ключи, персональные данные и полные выгрузки в любом файле.
- Расширение authority, неявный egress или собственный runtime, launcher,
  установщик и сетевая зависимость: это выходит за границы продукта
  (см. `docs/ARCHITECTURE.md` → «Разделение авторинга и исполнения»).
- Дублирование тела skill в адаптере: адаптер даёт только installation
  и invocation mapping.
- Изменение семантики `existing` / `greenfield` или словаря статусов без
  отдельного решения владельца.

## Согласованность поставки

`MANIFEST.md` — positive allowlist: файл, отсутствующий в списке, не является
частью поставки. Если PR добавляет, удаляет или переименовывает файл переносимой
поставки, он обязан обновить и список, и счётчики в разделе `Counts`.

Файлы управления репозиторием (`LICENSE`, `CHANGELOG.md`, `CONTRIBUTING.md`,
`SECURITY.md`, `.github/**`, `.gitattributes`, `.gitignore`) в переносимую
поставку не входят и учитываются отдельным разделом манифеста.

## Стиль

- Язык документации — русский; английские термины сохраняются там, где они
  являются частью контракта: `existing`, `greenfield`, `evidence`, `workflow`,
  `skill`, `agent`, `PASS`, `FAIL`, `UNKNOWN`, `NOT_RUN`, `BLOCKED`.
- Переводы строк — `LF` (зафиксировано в `.gitattributes`).
- Термины употребляются в значении из [docs/GLOSSARY.md](docs/GLOSSARY.md).

## Чего здесь нет

Процесса CI, автоматических проверок и раннера тестов в этом репозитории нет —
QAEF не поставляет инфраструктуру исполнения. Проверка изменения выполняется
чтением: сверкой утверждений с файлами и статусами.
