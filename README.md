# TouchStone Prompt QA Engineering Framework (QAEF)

QAEF — продукт TouchStone Studio для инженеров по автоматизации тестирования. Он помогает сопровождать существующий тестовый фреймворк или построить новый с нуля. Его агенты и skills создают и изменяют реальный тестовый код в целевом репозитории, когда у них есть явно выданное право на запись.

QAEF соединяет prompt engineering, context engineering и практику тестовой автоматизации. Это не набор советов: результатом работы должны быть проверяемые изменения тестов и test-support в границах задачи либо честно зафиксированная причина остановки.

## Что даёт QAEF

- Помогает выбрать тестовый слой, сценарии и данные по требованию или риску.
- Сохраняет доказанные команды, паттерны и архитектуру уже работающего фреймворка.
- Проектирует минимальный вертикальный каркас для нового фреймворка в стеке, который выбрал пользователь.
- Создаёт unit, contract, API, integration, UI, load и security тесты, а также нужные fixtures, mocks, clients и helpers.
- Передаёт результат с evidence, известными ограничениями и открытыми рисками.

## Два равноправных режима

| Режим | Когда выбирать | Первый шаг |
|---|---|---|
| `existing` | В целевом репозитории уже есть тесты или тестовый фреймворк. | Сначала `$qaef-map-framework`; до карты тесты не редактируются. |
| `greenfield` | Фреймворка нет либо пользователь явно решил создать его с нуля. | `$qaef-init`, затем `framework-blueprint`. |

Переход между режимами требует явного решения пользователя. QAEF не заменяет существующую архитектуру молча и не навязывает собственный универсальный раннер.

## Границы

QAEF описывает контракты, агентов, skills, шаблоны и рабочие процессы. Он не поставляет встроенный runtime, инфраструктуру запуска, установщики или сетевые зависимости. Команды запуска и окружение остаются собственностью целевого проекта.

## Начать за пять минут

1. Откройте [START-HERE.md](START-HERE.md) и выберите ровно один режим.
2. Передайте агенту первый промпт из выбранного маршрута.
3. Получите карту существующего фреймворка либо проект `framework-blueprint`.
4. Только после этого проектируйте и пишите тестовый код в целевом репозитории.
