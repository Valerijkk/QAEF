# Словарь терминов QAEF

Термины употребляются в этом значении во всех файлах поставки. Английские слова
сохранены там, где они являются частью контракта и не переводятся.

## Режимы

| Термин | Значение |
|---|---|
| `existing` | Режим для целевого репозитория, в котором тесты или тестовый фреймворк уже есть. Работа начинается с доказанной карты; до её завершения тесты не редактируются. |
| `greenfield` | Режим для целевого репозитория, в котором фреймворка нет либо пользователь явно решил создать его с нуля. Стек выбирает пользователь. |
| Переход между режимами | Отдельное решение пользователя. Агент не меняет режим самостоятельно. |

## Задача и полномочия

| Термин | Значение |
|---|---|
| Task contract | Полный набор входов роли: `objective`, `mode`, границы путей, `inputs`, `acceptance`, `authority`, `allowed_tools`, `stop_conditions`, `handoff_recipient`. |
| `authority` | Отдельно выданные права `read`, `write`, `execute`, `egress`. Имя агента, название skill и текст промпта полномочий не добавляют. |
| Literal scope | Конечный список конкретных путей без неоговорённых glob-шаблонов, скрытого расширения корня и «соседних полезных файлов». |
| `owned_paths` | Пути, которые роль вправе создать или изменить. Для полностью read-only запуска — пустой список. |
| `excluded_paths` | Явно запрещённые пути. Для тестовых задач сюда всегда входит production-код. |
| Write-authority | Явно выданное право записи. Без него результатом задачи на реализацию является `BLOCKED`, а не совет. |
| Stop condition | Заранее заданное условие, при котором роль останавливается и возвращает `BLOCKED`, `UNKNOWN` или `NOT_RUN` вместо догадки. |

## Контекст

| Термин | Значение |
|---|---|
| Context packet | Наименьший достаточный набор доказательств для одного решения в одной задаче. Не копия репозитория и не история обсуждений. |
| Provenance | Происхождение источника: кто или что его предоставило. |
| Freshness | Дата или ревизия источника, либо `UNKNOWN`. |
| Факт | Наблюдаемое содержимое источника с provenance. |
| Вывод | Объяснение, следующее из фактов; помечается как вывод и содержит опоры. |
| Неизвестное | Отсутствующая, противоречивая или недостаточно свежая информация. Обозначается буквально `UNKNOWN` и не превращается в вывод ради завершённого вида отчёта. |
| Конфликт источников | Ситуация, в которой обе позиции сохраняются с указанием их источников и владельца решения. Удобная версия молча не выбирается. |

## Тесты и evidence

| Термин | Значение |
|---|---|
| Traceability | Связь теста с требованием, риском или TC — либо честная фиксация того, что связи нет. |
| Oracle | Источник истины об ожидаемом поведении, по которому строится assertion. |
| Assertion sensitivity | Свойство assertion обнаруживать дефект. Доказывается корректным RED, controlled mutation или negative sentinel. |
| Controlled mutation | Намеренное изменение ожидаемого поведения, после которого тест обязан упасть. Если он проходит — assertion бесполезен. |
| Negative sentinel | Контрпример, который должен обнаружить ложный успех: например, тест, проходящий при доступе без нужного права. |
| Корректный RED | Наблюдаемое падение теста до реализации поведения. Имитировать failing baseline нельзя. |
| Test-support | Fixtures, clients, page objects, helpers, тестовые данные и oracles. Изменяется только в явно разрешённых путях. |
| Structural skeleton | Заранее утверждённые package markers, пустые placeholders и иные элементы каркаса, не несущие поведение. |
| Матрица сценариев | Группы, применимость которых рассматривается для каждой задачи: happy, negative, authn, authz, boundary, edge, corner, failure-recovery. |
| Conclusion-blind verification | Независимая проверка, при которой reviewer получает задачу, входы, артефакты и rubric, но не вывод автора и не его ожидаемую оценку. |
| Rubric | Фиксированный набор измерений, по которым оценивается результат. |
| Handoff | Передача следующему владельцу: изменённые пути, evidence, статусы, ограничения, риски и одно следующее действие. |

## Статусы

Допустимы ровно пять значений. Ни одно из них само по себе не означает
готовность, отсутствие дефектов или экономический эффект.

| Статус | Значение | Частая ошибка |
|---|---|---|
| `PASS` | Требуемое evidence получено и проверено в заявленной границе | Читать как «готово к продакшену» |
| `FAIL` | Evidence противоречит критерию или результат не достигнут | Читать как указание на виновника |
| `UNKNOWN` | Данных недостаточно, вывод не делается | Читать как «проблемы нет» |
| `NOT_RUN` | Нужная проверка ещё не запускалась | Читать как `FAIL` или как «не нужна» |
| `BLOCKED` | Требуется недостающее решение, контекст или authority | Читать как «инструмент не работает» |

## Границы продукта

| Термин | Значение |
|---|---|
| Authoring framework | То, чем QAEF является: определяет, как собрать контекст, спроектировать тесты, внести разрешённые изменения и передать evidence. |
| Execution tools | То, чем QAEF не является: команды, runner, окружение и CI целевого проекта. Принадлежат самому проекту. |
| Адаптер | Тонкий слой представления, дающий только installation и invocation mapping. Не создаёт семантику, полномочия и runtime. |
| Параллельная архитектура | Второй тестовый корень, клиент или конфигурация, созданные агентом вместо использования доказанных проектных. Отклоняется. |
